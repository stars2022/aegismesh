### 竞标模式的准确定位

产品名称沿用用户确定的“竞标模式”，技术描述建议固定为“**有界任务板自主认领协作**”。当前成员自行提出、认领和执行任务，提交证据并复核同伴成果，协调者负责最终复核和汇总。参与范围是符合约束的本站托管成员，默认 3 名成员、6 项任务、120 秒认领有效期；开关默认关闭。

它与合同网的分布式任务分配、黑板系统的共享状态，以及 Agensh 的自主认领有思想关联。但目前没有报价、竞价比较、择优中标、真实付款或开放外部参与者市场；也不是完全去中心化系统。没有这些机制，就不能写成实现了完整拍卖协议、市场均衡或激励相容性。

竞标模式目前有隔离回归与界面样例，尚未证明真实模型的任务划分质量、重复劳动减少、成本下降或科研产出提升。原报告早于该功能，不应把缺少这一节判为当时报告的事实错误。

## 三、理论与服务选择研究

### T1 合同网协议

Reid G. Smith，1980。[The Contract Net Protocol: High-Level Communication and Control in a Distributed Problem Solver](https://publications.gc.ca/site/eng/9.950444/publication.html)。IEEE Transactions on Computers，C-29(12)，1104–1113；DOI：10.1109/TC.1980.1675516。链接为作者所属机构的政府出版物记录，提供 1982 年重印件，原论文年份是 1980 年。

支持点：通过任务承包协商分配分布式工作，为任务发布、参与者选择和协作提供经典背景。用于竞标模式“相关工作”，不要说当前抢先认领机制完整实现了合同网。具体发布—投标—授予流程可同时引用 T9。

### T2 黑板系统

Lee D. Erman、Frederick Hayes-Roth、Victor R. Lesser、D. Raj Reddy，1980。[The Hearsay-II Speech-Understanding System: Integrating Knowledge to Resolve Uncertainty](https://mas.cs.umass.edu/Documents/Erman_Hearsay80.pdf)。ACM Computing Surveys，12(2)，213–253；DOI：10.1145/356810.356816。已核对原文摘要及黑板结构部分。

支持点：独立知识源围绕共享状态开展机会驱动的协作。任务板的共享进度、依赖和成果可借此解释。原研究是语音理解系统，不是 LLM 任务拍卖；当前任务板也不是它的完整复现。

### T3 协调理论

Thomas W. Malone、Kevin Crowston，1994。[The Interdisciplinary Study of Coordination](https://ccs.mit.edu/papers/CCSWP157.html)。ACM Computing Surveys，26(1)，87–119；DOI：10.1145/174666.174668。作者机构网页保存的是 1993 年工作稿，并注明 1994 年正式发表。

支持点：把协调理解为活动之间依赖关系的管理。可以将 AegisMesh 的子任务依赖、输入资料交接、共享画布冲突、成员负载和停止条件统一解释，而不是把协作简化为“多个角色轮流说话”。它不直接证明某种编排优于另一种。

### T4 多属性决策与 TOPSIS

Ching-Lai Hwang、Kwangsun Yoon，1981。[Multiple Attribute Decision Making: Methods and Applications — A State-of-the-Art Survey](https://link.springer.com/book/10.1007/978-3-642-48318-9)。Springer，Lecture Notes in Economics and Mathematical Systems，第 186 卷；DOI：10.1007/978-3-642-48318-9。这是方法专著，已核对出版社信息；不是本次逐章全文审读。

支持点：为多属性选择及理想解距离排序提供经典出处。用于路由公式的理论背景。指标构造、权重、正向化和距离选择依然需要说明；TOPSIS 本身不能证明当前候选排名等于实际业务最优。

### T5 信息熵

Claude E. Shannon，1948。[A Mathematical Theory of Communication](https://people.math.harvard.edu/~ctm/home/text/others/shannon/entropy/entropy.pdf)。Bell System Technical Journal，第 27 卷，379–423、623–656。原文由大学公开保存；另有 [Bell Labs 出版记录](https://www.nokia.com/bell-labs/publications-and-media/publications/a-mathematical-theory-of-communication/)。

支持点：提供信息熵的定义基础。AegisMesh 用候选指标分布的熵计算请求级区分度，是决策层的应用选择；不能从香农理论推出“越离散的指标越重要”或“28% 熵权一定最好”。服务选择中的实际应用见 T10。

### T6 Beta–Binomial 贝叶斯更新

Andrew Gelman、John B. Carlin、Hal S. Stern、David B. Dunson、Aki Vehtari、Donald B. Rubin，2013。[Bayesian Data Analysis，第三版](https://sites.stat.columbia.edu/gelman/book/)。Chapman & Hall/CRC，方法教材。[作者公开电子版](https://sites.stat.columbia.edu/gelman/book/BDA3.pdf)第 2 章讨论二项数据、共轭先验和先验敏感性；本次核对了相关可检索章节片段，并未通读整本教材。

支持点：在相应二项模型假设下，Beta(α,β) 先验观察到 s 次成功、f 次失败后，后验均值为 `(α+s)/(α+β+s+f)`。代码的 `(s+2)/(s+f+4)` 对应 Beta(2,2) 平滑。选择 2、2 是工程先验，不是教材给本平台的最优参数；应注意样本选择、任务难度差异和环境漂移。技术执行成功也不等于内容正确。

### T7 乐观并发控制

H. T. Kung、John T. Robinson，1981。[On Optimistic Methods for Concurrency Control](https://www.cs.cmu.edu/afs/cs.cmu.edu/academic/class/15712-s05/www/readings/kung81.pdf)。ACM Transactions on Database Systems，6(2)，213–226；DOI：10.1145/319566.319567。原文由作者机构保存。

支持点：执行后验证冲突是处理共享数据的一种经典思路。共享画布的基线版本检查、冲突拒绝与修订留痕可类比说明。应用层版本检查不等于完整实现该数据库算法，也不意味着 SQLite 没有写锁。

### T8 有限期租约

Cary G. Gray、David R. Cheriton，1989。[Leases: An Efficient Fault-Tolerant Mechanism for Distributed File Cache Consistency](https://web.stanford.edu/class/archive/cs/cs240/cs240.1046/readings/89-leases.pdf)。SOSP 1989，202–210；会议论文 DOI：10.1145/74850.74870。已核对原文租约定义与故障假设。

支持点：用有限有效期避免权利无限悬挂。当前认领租约可借此解释，但必须与数据库条件更新、有效凭据校验和过期处理一起描述。原文面向文件缓存及特定故障模型；租约本身不能保证任务副作用只发生一次。

### T9 合同网的定量分析

Cheng Gu、Toru Ishida，1995。[A Quantitative Analysis of the Contract Net Protocol](https://cdn.aaai.org/ICMAS/1995/ICMAS95-075.pdf)。第一届 International Conference on Multiagent Systems，449 页。

支持点：原文明确区分发布任务、承包者投标和管理者授予，并用模拟分析负载、成员数量与同质性对效用的影响。用于解释“竞标”名称与当前自主认领实现的差别，也提示同质成员可能集中争抢。它是模拟研究，不是当前 LLM 运行效果证明。

### T10 云服务选择的混合权重研究

Sameer Singh Chauhan、Emmanuel S. Pilli、R. C. Joshi，2021。[BSS: a brokering model for service selection using integrated weighting approach in cloud environment](https://link.springer.com/article/10.1186/s13677-021-00239-5)。Journal of Cloud Computing，10，26；DOI：10.1186/s13677-021-00239-5。已读摘要、权重公式和实验设置。

支持点：异构服务选择已有将用户偏好与基准指标结合、用熵计算客观权重的研究。这比只引用 Shannon 更贴近我们的路由问题。其数据、权重获取与最终排序方式不同，实验也含模拟与构造反馈；不能把它的排名稳定性和运行时间结果移植到 AegisMesh。混合主客观权重不宜写成我们的首创。

## 四、现代智能体与评测论文

除明确注明会议发表者外，下列采用已核对的 arXiv 版本作为引用依据，不额外推定其同行评审状态。

### P1 推理与行动交替

Shunyu Yao 等，2022 预印本／ICLR 2023。[ReAct: Synergizing Reasoning and Acting in Language Models](https://arxiv.org/abs/2210.03629)。

支持点：将推理、工具动作和环境反馈放在交互循环中。对应协调与执行智能体的工具闭环、检索回执和后续决策；不是“展示推理文字即可保证正确”。

### P2 检索支撑生成

Patrick Lewis 等，2020，NeurIPS 2020。[Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks](https://arxiv.org/abs/2005.11401)。

支持点：用外部可检索知识支撑知识密集型生成。对应文献、新闻检索与来源化上下文。原论文采用特定检索器和生成模型训练框架；我们的网页搜索、阅读与引用不宜直接写成完整复现了该 RAG 系统。

### P3 可编程多智能体对话

Qingyun Wu 等，2023 预印本。[AutoGen: Enabling Next-Gen LLM Applications via Multi-Agent Conversation](https://arxiv.org/abs/2308.08155)。

支持点：模型、工具与人可通过可配置对话模式协作。用于对比平台的协调—执行角色、群体讨论和工具编排；它不是 AegisMesh 的跨平台身份或官方互联协议来源。

### P4 标准化角色与交接

Sirui Hong 等，2023 起的预印本。[MetaGPT: Meta Programming for A Multi-Agent Collaborative Framework](https://arxiv.org/abs/2308.00352)。

支持点：用角色分工、标准流程和中间成果约束降低协作歧义。对应成果格式、任务指令与交接审核。其主要软件开发实验不能直接证明新闻或科研任务的质量。

### P5 分阶段协作

Chen Qian 等，2023 预印本／ACL 2024。[ChatDev: Communicative Agents for Software Development](https://arxiv.org/abs/2307.07924)。

支持点：专门角色通过阶段性沟通完成软件开发流程。可用于说明工作流模式为什么需要阶段交接与明确职责；不能据此保证增加讨论轮数就提高质量。

### P6 中央协调的通用系统

Adam Fourney 等，2024 预印本。[Magentic-One: A Generalist Multi-Agent System for Solving Complex Tasks](https://arxiv.org/abs/2411.04468)。

支持点：协调者规划、跟踪和重规划，专门成员执行工具任务。与现有协调分派更接近，是竞标模式的架构比较对象。其基准成绩不是本平台成绩，也不意味着必须复制其工具与控制器。

### P7 自主认领与共享上下文

Zhihao Zhan、Ting Song、Li Dong、Shaohan Huang、Jianxun Lian、Yan Xia、Furu Wei，2026。[Agensh: Scaling Organizational Intelligence to 1,024 Agents](https://arxiv.org/abs/2609.26781v1)。2026 年 9 月 22 日提交的第 1 版预印本。

支持点：没有中央编排者的协作循环，成员结合共享上下文自主认领、执行、交流并验证成果。它是当前竞标模式最直接的设计参考。实验针对 ProgramBench 五个最难编码任务，不能推广成所有科研、新闻、旅游任务都受益，也不能把论文的大规模效果归给本平台。我们的实现有成员上限、中心任务状态和最终协调复核，属于有界借鉴。

### P8 学习式模型路由

Isaac Ong 等，2024 起的预印本。[RouteLLM: Learning to Route LLMs with Preference Data](https://arxiv.org/abs/2406.18665)。

支持点：利用偏好数据，在模型质量与调用成本之间进行路由。对应成本质量权衡和基线选择。它主要选择强弱模型；我们选择具有协议、能力和运行状态约束的智能体，且没有训练这种偏好路由器。

### P9 低成本模型级联

Lingjiao Chen、Matei Zaharia、James Zou，2023 预印本。[FrugalGPT: How to Use Large Language Models While Reducing Cost and Improving Performance](https://arxiv.org/abs/2305.05176)。

支持点：用模型选择、级联与其他策略研究成本质量权衡。适合作为成本控制的相关工作和可选对照；论文中的节省比例不能写成我们的实际节省。

### P10 多智能体辩论

Yilun Du、Shuang Li、Antonio Torralba、Joshua B. Tenenbaum、Igor Mordatch，2023 预印本。[Improving Factuality and Reasoning in Language Models through Multiagent Debate](https://arxiv.org/abs/2305.14325)。

支持点：在特定推理与事实任务上研究多轮观点交换。用于群体讨论与同伴复核的相关工作。成员意见一致不是事实认证，尤其不能忽略共用模型带来的相关错误。

### P11 自反馈修订

Aman Madaan 等，2023 预印本。[Self-Refine: Iterative Refinement with Self-Feedback](https://arxiv.org/abs/2303.17651)。

支持点：同一模型生成反馈并修订成果，是同伴审核实验必须考虑的较简单基线。不能在没有比较的情况下，将改进全部归因于“不同智能体互审”。

### P12 长上下文的位置问题

Nelson F. Liu 等，2023 起的论文版本，页面注明已被 TACL 接收。[Lost in the Middle: How Language Models Use Long Contexts](https://arxiv.org/abs/2307.03172)。

支持点：相关信息在长上下文中的位置可能影响利用效果。用于解释为何筛选任务相关片段而不是默认复制整段会话。并不直接证明我们选择算法有效，也不意味着所有新模型都有相同退化幅度。

### P13 多智能体失败分类

Mert Cemri 等，2025 预印本。[Why Do Multi-Agent LLM Systems Fail?](https://arxiv.org/abs/2503.13657)。

支持点：研究跨多个系统的失败轨迹，提出覆盖设计、智能体间错位、任务验证与终止等问题的 MAST 分类。用于构建异常标签、审计事件和验收表；不能据此证明平台已消除这些失败。

### P14 多智能体扩展的适用条件

Yubin Kim 等，2025 首次提交／2026 年 4 月 8 日第 3 版。[Towards a Science of Scaling Agent Systems](https://arxiv.org/abs/2512.08296v3)。

支持点：在受控设置中比较单智能体与不同协作结构，收益取决于任务可分解性、通信开销和错误传播。本次采用第 3 版的 260 个配置、6 个基准口径，不混用旧版的 180 个配置、4 个基准。用于支撑“按任务选择协作方式”，不是“智能体越多越好”。

### P15 交互式智能体评测

Xiao Liu 等，2023 预印本／ICLR 2024。[AgentBench: Evaluating LLMs as Agents](https://arxiv.org/abs/2308.03688)。

支持点：在交互环境中评价推理、决策与指令执行。可借鉴多场景验收结构；自建问题列表测试不能标成 AgentBench 成绩。

### P16 真实助理问题基准

Grégoire Mialon 等，2023 起的预印本。[GAIA: a benchmark for General AI Assistants](https://arxiv.org/abs/2311.12983)。

支持点：面向需要推理、浏览和工具使用的现实助理问题。适合设计有确定参考答案和可核查资料的科研、新闻、旅游任务；不能把“有题目、有输出”直接称为通过 GAIA。

### P17 业务终态与重复可靠性

Shunyu Yao、Noah Shinn、Pedram Razavi、Karthik Narasimhan，2024 预印本。[τ-bench: A Benchmark for Tool-Agent-User Interaction in Real-World Domains](https://arxiv.org/abs/2406.12045)。

支持点：结合用户交互、领域规则和工具操作，按最终数据库状态评价任务。其 `pass^k` 关注重复执行均成功的可靠性，不是任意一次成功的 `pass@k`。对应账号权限、任务完成、配额扣减与异常收尾的终态检查。

### P18 不可信工具内容与提示注入

Edoardo Debenedetti 等，2024 预印本。[AgentDojo: A Dynamic Environment to Evaluate Prompt Injection Attacks and Defenses for LLM Agents](https://arxiv.org/abs/2406.13352)。

支持点：工具返回中不可信文本可能干扰代理行为，防御要在动态任务和攻击中评价。用于说明上下文信任边界、资料标记和注入测试的必要性；现有片段审核与任务绑定不等于已经通过该基准。

## 五、行业实证研究

这一组比厂商宣传更适合讨论实际收益与部署问题。每项仍有样本和任务边界，不能直接转换成 AegisMesh 的用户规模、准确率或节省比例。

### E1 生产中的智能体

Melissa Z. Pan 等，2025 首次提交，2026 年 6 月 4 日第 4 版。[Measuring Agents in Production](https://arxiv.org/abs/2512.04123v4)。页面注明 ICML 2026 Oral；已核对全文调查方法。

研究依据：306 份有效调查中筛选出 86 份生产或试点部署样本，并结合 20 个案例访谈；各问题有效回答人数可能不同。当前摘要的 86 与早期版本的 306 不是可互换分母。

支持点：实际部署重视可靠性、受限工作流、提示工程、人工评价与运行管理。这与平台的工具轮次上限、审计和错误收尾相符。样本来自专业网络且有选择偏差，不能当作全球企业采用率或本地教授需求调查。

### E2 客服场景的真实部署效果

Erik Brynjolfsson、Danielle Li、Lindsey Raymond，2025。[Generative AI at Work](https://academic.oup.com/qje/article/140/2/889/7990658?login=false)。The Quarterly Journal of Economics，140(2)，889–942；DOI：10.1093/qje/qjae044。

研究依据：正式发表版本分析 5,172 名客服人员的渐进式工具部署，平均每小时解决问题数提高约 15%，收益随使用者经验等因素而异。不是本文自行实施的随机对照试验。不要混用 2023 年工作稿的 5,179 人、14% 口径。

支持点：面向具体任务的 AI 辅助可能有实际生产价值，也需要区分使用者。不能把客服研究的 15% 写成科研工作台或麦溪数字人的收益。

### E3 知识工作的能力边界

Fabrizio Dell’Acqua 等，2026 正式发表。[Navigating the Jagged Technological Frontier: Field Experimental Evidence of the Effects of Artificial Intelligence on Knowledge Worker Productivity and Quality](https://www.hbs.edu/ris/Publication%20Files/dell-acqua-et-al-2026-navigating-the-jagged-technological-frontier_5c589c8c-fbb5-458f-b285-c944746cd717.pdf)。Organization Science；DOI：10.1287/orsc.2025.21838。早期工作稿为 2023 年；本次采用 2026 年正式论文原文。

研究依据：758 名顾问的预注册随机实验；能力边界内任务有收益，边界外任务可能降低正确性。

支持点：路由、任务适配与结果复核比笼统宣称“AI 提升所有知识工作”更有依据。样本是特定咨询企业和任务，不是对我们科研场景的直接评价。

### E4 经验开发者的反向结果

Joel Becker、Nate Rush、Beth Barnes、David Rein，2025。[Measuring the Impact of Early-2025 AI on Experienced Open-Source Developer Productivity](https://metr.org/Early_2025_AI_Experienced_OS_Devs_Study-paper.pdf)。METR 原始研究论文。

研究依据：16 名熟悉开源仓库的开发者、246 个真实任务，随机允许或不允许使用 AI；研究中允许 AI 的完成时间约增加 19%。这是 2025 年初特定工具与使用方式的结果，不是对所有 AI 或 2026 年模型的判断。

支持点：必须测端到端时间、理解与复核成本，而不只看生成速度。报告应保留反证，不能只引用正向收益论文。

## 六、行业报告与治理指南

### I1 企业 AI 与成本治理

McKinsey，2026 年 8 月 25 日。[The state of AI in 2026: On the road to ROI](https://www.mckinsey.com/capabilities/quantumblack/our-insights/the-state-of-ai)。

研究依据：2026 年 5–6 月在线调查，1,719 名参与者、97 个国家，按国家 GDP 加权。它反映受访者报告的采用与经营情况，不是因果实验。

支持点：AI 使用扩大并不自动产生可衡量 ROI，运行成本和规模化治理有实际压力。可放背景与账号配额模块的设计动机。不能把大企业子样本的智能体规模化比例套给所有组织，也不能拿问卷直接估算我国高校采购规模。

### I2 人的控制与组织采用

Microsoft Work Trend Index，2026 年 5 月 5 日。[Agents, human agency, and the opportunity for every organization](https://www.microsoft.com/en-us/worklab/work-trend-index/agents-human-agency-and-the-opportunity-for-every-organization)。

研究依据：10 个市场、20,000 名已经使用 AI 的知识工作者调查，结合厂商的其他研究材料。受访者不是全体劳动者，10 个市场不含中国。

支持点：组织采用需要工作流、治理与人的控制权配套。对应管理员开关、角色、配额、可停止协作与可追踪运行。属于厂商研究，自报告关联不等于治理功能造成了业绩提升。

### I3 能力与治理的宏观背景

Stanford HAI，2026。[The 2026 AI Index Report](https://hai.stanford.edu/ai-index/2026-ai-index-report)。[完整报告](https://hai.stanford.edu/assets/files/ai_index_report_2026.pdf)。

支持点：提供模型能力、应用、投资和风险的年度综合背景，说明能力增长与评价、治理仍有差距。它是多来源汇编，不是一项单独的对照实验；正文如引用某个具体图表，应再标出该章、图号、统计年份和底层来源。

### I4 国内政务智能体架构研究

中国信息通信研究院。[政务智能体发展研究报告（2025年）](https://www.caict.ac.cn/kxyj/qwfb/ztbg/202512/P020260119582840118218.pdf)。标题年度为 2025；本次核对了官方可检索原文第 11 页的架构论述，不以文件路径推断正式发布日期。

支持点：报告将数据知识、资源访问、智能能力、多智能体协同、应用等层次，与贯穿全生命周期的运维、安全保障结合。可用于国内行业背景及平台分层设计比较。它不是强制国家标准，也不能证明我们的公开 demo 具备政务合规、采购资格或大规模部署能力。

### G1 生成式 AI 风险管理

NIST，2024。[Artificial Intelligence Risk Management Framework: Generative Artificial Intelligence Profile](https://nvlpubs.nist.gov/nistpubs/ai/NIST.AI.600-1.pdf)。NIST AI 600-1，风险管理指南，不是论文或认证证书。

支持点：指南讨论虚构内容、隐私、信息安全和组件集成风险，并建议验证输出来源、记录泛化边界、持续监测和事件响应。重点参考 MS-2.5-001、MS-2.5-003、MS-2.6-005 与 MANAGE 4.1。适合解释审计与验收设计；不能据此写“已经 NIST 认证”或“满足全部法定要求”。

## 七、可融入报告的段落

以下是建议稿，外部研究结论与平台设计分开陈述。整合时应按报告统一编号引用，并保留原有代码、测试与快照来源。

### 背景与需求

生产中的智能体应用并不是简单地把模型接入工具。对已部署或试点系统的研究显示，可靠性、有限的执行流程、人工评价与运行管理是实际工程的重要关注点（E1）。企业调查也表明，使用范围扩大并不等于已经实现稳定的经营收益，成本与治理仍需要独立管理（I1）。因此，AegisMesh 将目标限定为异构智能体的受控互联与协作：在调用前判断资格，在执行中约束资源和上下文，在交付后保留可核对结果。上述行业证据解释设计动机，并不替代针对本平台目标用户的需求调研。

### 协作架构与相关工作

协调理论将协作问题理解为活动之间依赖关系的管理，而不是参与者数量的增加（T3）。现代多智能体系统探索了可编程对话、角色化流程和中央协调等结构（P3–P6），但协作也会引入交接错位、验证不足和错误传播（P13–P14）。AegisMesh 保留协调分派、逐步工作流和群体讨论，并把上下文选择、任务关联、执行预算和成果收尾作为共同运行边界。其工程特点在于将这些控制与异构身份和传输约束结合，而不是宣称提出了所有协作范式的通用最优结构。

### 路由方法的理论依据

异构智能体选择同时涉及能力与服务质量，适合按多属性决策问题建模（T4、T10）。平台先构造满足协议与运行约束的候选域，再将能力匹配、历史可靠性、用户反馈、时延、负载、健康和估算成本统一用于排序。其中历史比例采用 Beta 先验平滑（T6），候选区分度采用基于信息熵的权重（T5、T10），与管理员偏好融合后进行 TOPSIS 排序。72/28 的权重融合及 80/20 的分数混合均是当前工程参数，尚未证明最优，也未证明综合分是经统计校准的成功概率。成本质量权衡的现代相关工作包括 P8–P9，但本平台并未复现其学习路由器或成本收益。

### 竞标模式

作为中央分派的可选补充，平台增加有界任务板自主认领协作。其思想与合同网的分布式任务选择、黑板系统的共享状态以及 Agensh 的自主认领循环相关（T1–T2、T9、P7）。成员自行提出任务、认领、执行、提交证据和复核同伴成果，协调者进行最终复核与汇总。平台以有限成员、有限任务、认领有效期和原有用量约束限制运行扩展。当前产品名称为“竞标模式”，但没有报价和择优授予机制；属于工程借鉴，而非合同网、拍卖市场或 Agensh 大规模实验的完整复现。真实模型收益仍待独立对照验收。

### 上下文与运行治理

长上下文不保证模型充分利用相关资料，工具返回内容也可能携带不可信指令（P12、P18）。平台因此要求协调者明确选择与本任务相关的参考片段，并在运行侧检查审核标识和任务关联，不自动传递完整历史。账号、会话和调用的归属、资源额度、操作审计以及关闭开关后的在途收尾，承担运行治理职责。风险管理指南强调来源验证、部署边界与持续监测（G1）；这些依据支持分层控制的必要性，但不能证明现有实现已经消除注入、隐私或虚构内容风险。

### 评价与适用边界

首轮 100 题验证说明了指定配置下的根任务提交、协调派发、执行返回与收尾能力，不等于内容正确率或科研收益。智能体评测应检查目标终态、规则遵守、资料依据和重复执行的一致性（P15–P17）。行业实证既观察到特定客服与知识工作任务的收益，也发现某些熟悉仓库的开发任务出现时间损失（E2–E4）。因此，后续实验应在固定任务、模型、资料和预算下，同时报告内容质量、引用正确性、端到端时延与真实成本；官方计数仅作为互联链路的辅助证据。

## 八、最值得补的实验

以下仅为实验设计，不在本次阅读过程中发起业务调用、豁免额度或增加排行榜计数。

| 待回答的问题 | 最小对照 | 核心指标与约束 |
| --- | --- | --- |
| 协作是否值得增加成本 | 单执行者、中央协调、固定工作流、自主认领；使用相同问题与资料 | 人工盲评内容、证据正确率、总 token 与金额、端到端 p50/p95；统一总预算，成员多不能获得额外预算 |
| 路由各项设计是否有效 | 硬约束后随机、纯管理员加权、纯 TOPSIS、完整方案；分别移除 Beta、熵权、绝对效用修正 | 任务完成、内容质量、选中成员成本、资格违规；开发集调参数，独立测试集报告结果 |
| 候选变化是否导致不稳定 | 增加劣势候选、同质候选，模拟小样本或状态漂移 | 排名变化、权重变化、冷启动偏差；绝对效用混合不能先验保证无排序逆转 |
| 竞标模式是否减少重复劳动 | 有分工边界的任务与强顺序依赖任务分层；对比中央模式 | 语义重复任务率、未认领率、有效成果率、审核否决率、通信开销；不只检查标题精确重复 |
| 同伴审核是否有增益 | 无审核、单模型自修订、不同成员互审 | 注入已知事实错误或缺失引用，盲评检出和误拒；审核者不能知道参考答案 |
| 上下文审核是否改善质量与安全 | 在隔离夹具中比较完整历史、相关片段与显式审核；引入不可信工具资料 | 正常任务可用性、非授权信息传播、攻击成功率；使用虚构数据，不测试生产用户记录 |
| 故障边界是否可信 | 超时、429、关闭模块、取消、租约过期、晚到提交、进程中断 | 是否停止新工作、在途状态、扣费归属和凭据拒绝；先夹具与测试供应商，再考虑经授权的真实环境 |
| “完成”是否可重复 | 固定同一任务独立重复，而不是只挑最好的一次 | 所有尝试均计入分母；区分 `pass^k` 与 `pass@k`，报告区间及未完成原因 |

可先建立 30–60 个有评分标准的保留题，按科研、新闻、旅游及依赖结构分层。含时效任务冻结资料和评价时点，缺资料时接受明确拒答或补充请求，不能强迫模型编造。由非开发者或不了解模式的评分者评价来源、覆盖、错误与可用性。

真实调用规模须另行确认成本和配额。初期适合先完成低成本夹具和小样本；再对主要模式做配对重复，避免把模式差异、模型差异和时间漂移混在一起。即使增加任务，也不能以冲榜作为实验停止标准。

### 行业价值的后续验证

科研工作台应记录从问题到可用材料的总时间、需要人工纠正的事实和引用、用户是否采纳，以及适用与不适用任务。麦溪界面还需要目标使用者的可读性、可操作性和理解测试；人格、播报和动作并非效率收益的替代指标。行业报告只能提供外部背景，不能替代这类用户研究。
