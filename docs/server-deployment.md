# 新服务器一键部署

入口：`bash scripts/deploy-server.sh`。本次目标为 `111.91.23.163`，SSH 用户 `root`、端口 `22`。

这是正式前后端的**全新独立安装**，不是离线演示，也不是旧机器的配置迁移。用户已澄清本次是安全测试靶机，不是生产切换：使用 `--mode lab` 明确通过公网 IP/HTTP 发布，无需域名。默认仍只检查，显式 `--apply` 才安装；不会自动切换生产域名、复制旧配置/数据库/账号/密钥、注册智能体、启用 MQ、变更防火墙或停止旧服务器。

本次已实际部署为 `http://111.91.23.163/`，公网健康检查返回 200。正式代码使用独立的空库和新生成的测试管理员，旧账号、模型密钥、证书和历史数据均未迁入。HTTP 仅适用于这个一次性测试环境；不得输入生产密码、模型供应商真实密钥或个人敏感数据。

## 执行

在本机项目目录运行：

```bash
# 只读检查 SSH、系统和磁盘
bash scripts/deploy-server.sh --host 111.91.23.163 --user root --port 22

# 全新 IP/HTTP 靶机：构建正式前端、校验后端、打包上传、安装并验收
bash scripts/deploy-server.sh --host 111.91.23.163 --user root --port 22 --mode lab --apply

# 如需私有待机而不是公开测试，省略 --mode lab
bash scripts/deploy-server.sh --host 111.91.23.163 --user root --port 22 --apply
```

要求本机 Python 3.11+、Git、Node/npm，以及可用的 SSH 密钥登录；需要时用 `--identity /absolute/path/to/key`。不会接收密码参数、把密码写进脚本或读取聊天历史中的凭据。主机首次连接使用 SSH 的 accept-new，后续主机指纹变化直接拒绝；指纹保存在私有的 `var/deploy-new-server/known_hosts`。首次指纹应与控制台核对。

目标要求 Debian 12+/Ubuntu 24.04+、Python 3.11+、systemd、足够磁盘和 root/免密 sudo。依赖从系统包仓库、Python 包仓库及项目已固定提交的 ACPs 官方 Git 仓库安装；Linux 虚拟环境重新创建，不上传 macOS 虚拟环境。网络或依赖失败会停止，不忽略错误、不关闭 TLS 检查。操作细节只进入服务器私有的 `install.log`，不回显环境文件。

## 两种明确区分的部署模式

`--mode lab`：Nginx 监听 `0.0.0.0:80`，访问 `http://<IP>/` 和 `/admin`；后端仍仅监听 `127.0.0.1:18081`。没有域名也可测试真实的应用 HTTP 接口。此模式禁止使用任何配置/数据库导入参数，保持管理员认证，不自动植入代码执行漏洞，不使用真实上游服务或真实身份。主机 SSH 管理权限与应用账号分离。

默认 `--mode standby`：只对本机提供服务，适用于生产迁移前的私有验收，而不是本次公开靶机。

安装目录 `/opt/aegismesh`，后台服务 `aegismesh-standby.service`，独立账号 `aegismesh`。Nginx 前端只监听 `127.0.0.1:18080`，后端只监听 `127.0.0.1:18081`。通过 SSH 隧道验收：

```bash
ssh -p 22 -L 18080:127.0.0.1:18080 root@111.91.23.163
```

打开 `http://127.0.0.1:18080/admin`。首次生成独立管理员，凭据仅保存为服务器上的 `/opt/aegismesh/initial-admin.json`（root-only），不打印到部署日志。旧服务的管理员不会迁入。模型与智能体由新后台重新配置；部署验收不会发起付费模型调用。

两种模式都强制关闭后台心跳、自动探测、MQ 消费和邮件发送，避免重复身份/消费者影响旧站。管理员认证始终开启；HTTP 测试模式使用非 Secure cookie，不可原样用于生产。以后如转生产，应单独配置 HTTPS、Secure cookie、域名或有效 IP 证书，并审核身份、证书和 MQ；不得把靶机配置当作生产加固方案。本脚本不表示生产流量已迁移或第三方互联已激活。

本次服务器只有约 800MB 内存，已自动建立独立 2GB 交换空间，将后端内存上限降为 640MB，进程仍为非 root 账号并启用 systemd 文件系统/权限隔离。交换空间由独立服务持久化，不重写 `/etc/fstab`。

## 保护与恢复

- 不覆盖已有 `/opt/aegismesh`、同名静态目录、服务或 Nginx 配置。重复执行拒绝安装，避免重置账号和数据；后续升级需要单独的分版本发布流程。
- 上传包限定业务源码和正式前端产物，不含 `.env`、数据库、证书、日志、演示视频或 Git/依赖目录；每个文件有大小与 SHA-256 校验，拒绝路径穿越、软链接及设备文件。
- 首次安装 Nginx 时抑制包安装自动启动，归档新包自带的默认欢迎页链接，防止意外开公网 HTTP；既有 Nginx 配置不覆盖。服务失败时撤销本次新增的服务与代理配置，保留数据和私有日志，不递归删除目录。
- 验收要求主页 200、API health 正常、未登录管理接口 401、普通 Web AIP 入口 404。待机模式检查前后端均为回环监听；靶机模式明确允许前端 IPv4 80，但后端仍必须是回环监听。失败不声明成功，不触发真实业务调用。
- 本次无需使用导入参数。工具额外保留成对的 `--env-file` / `--database-snapshot`，只有明确要求迁移时才可用；不能单独导入数据库丢失供应商加密密钥，也不接受带 WAL/在途任务的原始库。附件和证书不在此模式中自动迁入，不能用它替代完整迁移。

本地产物及结果位于 `var/deploy-new-server/<UTC时间-随机ID>/`（私有、Git 忽略）。无网络打包验证可用 `--package-only`；`--skip-build` 只用于明确已核验的正式前端产物；iCloud 占位文件阻塞时可以显式提供 `--source-cache`，每个缓存后端文件必须与 Git 索引 blob 哈希一致，否则拒绝打包。本次缓存前端的 117 个构建输入也已与索引逐项核对一致。脚本退出非零时检查私有安装日志，不直接反复覆盖执行。

本次先安装待机后按澄清发布靶机；发布前已确认无业务数据，并保存服务器基线 `/opt/aegismesh/lab-baseline-20261023T141918Z/`。完整应用程序、测试库和新配置均是新机独立生成，没有访问旧服务器。`install_server.py --publish-lab` 只允许从具有本工具来源标记、未导入数据且仍为空库的待机安装转换，拒绝转换已存在业务数据的生产环境。
