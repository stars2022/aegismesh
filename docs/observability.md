# 日志与审计

管理后台新增「日志与审计」入口，和原有「运行记录」并列。
运行记录继续展示业务任务与协同过程；日志页查看已有 AMP 互联事件和管理操作。
本功能是本地查询层，不改变官方 SDK 的日志内容、上报方式、签名或转发游标，也不主动发起外部任务。

## 查看和排障

- **互联日志**：调用、MQ 消息、系统事件、心跳、指标和 AMP 审计。默认隐藏高频心跳 / 指标，可在类型菜单切换。
- **管理审计**：登录 / 退出、智能体与供应商管理、提审 / 同步 / 证书操作、探针、发现导入、路由策略、访问配置和数据导入导出。记录服务端认证的操作人、动作、对象路径、请求 ID、HTTP 结果、耗时。路由策略保存安全字段的前后值，提审失败保存脱敏诊断。
- 支持关键字、AIC（报告方 / 调用方 / 被调用方）、任务 / trace / message / request ID、结果和时间筛选。点击详情中的关联标识，可以查看同一任务 / 链路的事件。
- 列表默认折叠，点开才取详情；JSON 字段再次折叠。每页最多 25 条；可手动刷新或开启 10 秒自动刷新。翻页或页面不可见时不自动刷新。
- 导出当前已应用筛选下的最新 **最多 2000 条脱敏记录**，格式为 JSONL。第一行说明匹配总数、实际导出数和是否截断；不是原始 AMP 签名日志下载。
- 「采集与保留」显示文件读取进度、最近检查时间、跳过的无效行 / 过期行、文件重建次数、发现的未读轮转缺口和本进程审计写入失败次数。

例如排查智能体提审：切换「管理审计」→ 搜索智能体 ID 或「提交智能体审核」→ 只看异常 → 展开记录查看 HTTP 状态、诊断信息与请求 ID。对外互调则在「互联日志」用完整任务 ID 关联 Access 和 Message 事件。

## 记录状态的边界

**本地有日志 ≠ MQ 已确认 ≠ AMP 平台已接收 ≠ 已计榜。**
当前没有接入可核验的 AMP 平台接收 / 计榜回执，界面明确显示「未接入 / 未确认」。
Message 中的 `send`、`receive`、`ack` 只是该消息的本地生命周期事件，不被当作平台接收证明。
管理审计只留在本地数据库，不冒充官方审计，不参与 AMP 上报。

只有实际落盘的 AMP 事件会进入列表，不保证每个内部函数或本地任务都有 AMP 日志。
管理审计从启用功能开始记录，不根据业务数据补造历史操作。
索引中即使记录了原事件有签名，也仅表示 `signature_present`；本地查询层没有执行验签。

## 数据最小化与权限

四个查询 / 导出接口均经过现有管理员认证，返回 `Cache-Control: no-store`：

```text
GET /api/admin/logs
GET /api/admin/logs/{id}
GET /api/admin/logs/status
GET /api/admin/logs/export
```

本地索引采用字段白名单：不复制请求 / 响应正文、认证头、Cookie、消息载荷、任意 attributes、私钥和证书签名原文。
保留的错误短文本还会屏蔽常见凭据格式，并移除 URL 用户名、密码、查询参数和 fragment。
管理审计中间件只观察路径、状态及服务端显式提供的安全摘要，不读取或缓存 HTTP 正文，不影响 SSE 流。
通用错误文本不应写入业务正文或未标记的秘密，源日志生产者仍需保持这一约束。

操作审计没有界面删除入口；业务数据库导入 / 导出不包含这些记录，替换业务数据不会删除审计。
它仍然是可由数据库管理员修改的本地记录，**不是第三方防篡改存证**。
审计写入失败会输出服务器错误日志并增加可见失败计数；不让已经完成的业务操作再次失败或重试。

## 部署和保留

启动时创建 `operational_logs` 和 `log_ingest_cursors` 两张新表，不更改现有任务记录。
使用部署脚本的 Web API 进程运行一个采集器；独立 mTLS 监听进程由 `scripts/serve.py` 设置 `LOG_INDEXER_ENABLED=false`，避免重复扫描。
若自行启动多个 API worker，需单独指定唯一的采集进程，不要在多个 worker 中同时启用。

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| `AMP_LOG_DIR` | `logs` | 已有 AMP 日志目录，与 SDK / forwarder 使用的目录一致 |
| `LOG_INDEXER_ENABLED` | `true` | 是否扫描本地 AMP 日志并维护保留范围 |
| `LOG_INDEX_INTERVAL_SECONDS` | `5` | 扫描间隔（秒） |
| `LOG_RETENTION_DAYS` | `7` | AMP 查询索引的天数上限 |
| `LOG_MAX_RECORDS` | `100000` | AMP 查询索引的条数上限 |
| `AUDIT_RETENTION_DAYS` | `90` | 本地管理审计的天数上限 |
| `AUDIT_MAX_RECORDS` | `50000` | 本地管理审计的条数上限 |

天数 / 条数任一上限先到即淘汰查询记录。关闭采集器不会关闭管理审计写入，但同时会暂停自动保留清理。
只清理数据库里的查询记录，**不删、改、截断原始 AMP 文件，也不移动上报游标**。
原始日志的磁盘容量及归档仍需由服务器运维策略管理；本功能不擅自改变官方转发的保留条件。

只扫描固定命名的六个 `amp_{access,message,heartbeat,system,metrics,audit}_aegismesh.jsonl` 文件，拒绝文件级符号链接与非普通文件；部署目录本身可采用现有共享目录链接。
每个文件单次最多扫描约 2 MiB / 2000 行，部分写入等待下一轮，超过 256 KiB 的单行跳过并计数。
以 SDK `log_id` 去重，无 ID 的旧格式以内容哈希兜底。保留独立读取位置和末尾指纹，支持文件替换及 copy-truncate 后重读。
不读取轮转后的归档文件；如果轮转时已知仍有未读内容，会保留缺口计数并提示。索引离线期间未观测到的旧文件不可能自动补回。
